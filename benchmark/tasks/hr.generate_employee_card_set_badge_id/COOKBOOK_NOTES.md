# Cookbook notes — hr.generate_employee_card_set_badge_id

## New / reinforced quirks

- `hr.employee` in Odoo 19 has **no `badge_id` field**. The field labelled "Badge ID" in the employee form is technically `barcode` (`addons/hr/models/hr_employee.py:206`). Any seed/check script that writes `badge_id` will silently succeed as an invalid-key no-op and tests will look like they "pass" without actually setting anything. Always `grep -n "badge_id\|barcode" addons/hr/models/hr_employee*.py` before building a badge-related task.
- The `_verify_barcode` constraint (`addons/hr/models/hr_employee.py:1287-1291`) rejects anything outside `[A-Za-z0-9]` or longer than 18 chars. Values like `BADGE-001`, `EMP_001`, `E M P 1` all raise `ValidationError`. Stick to alphanumeric, <=18 chars, no hyphen/underscore/space.
- Tab layout: The employee form's notebook tab with `name="hr_settings"` has `string="Settings"` — `click_tab(page, "Settings")` is correct, NOT "HR Settings".
- The **Print Badge** button is `invisible="not barcode"` — it is hidden while the field is empty. Any oracle that clicks it must do so AFTER saving the form (post-save rerender makes the button visible). For medium tasks it's a best-effort click; primary assertion is the field value.
- Seeding `barcode=False` explicitly is needed so that the diff engine sees a clean `set` edit on the field (vs a pre-populated random badge generated by `generate_random_barcode`).

No retries. Task is trivially BU-solvable — kept at tier 2 medium for deterministic coverage of the hr_employee Settings tab flow.
